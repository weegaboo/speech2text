# Технические подробности

Краткая инструкция по установке и запуску находится в [README](../README.md).

## Файлы и результаты

- Форматы: MP3, M4A, WAV, OGG, Opus, FLAC, AAC, AIFF, WMA, WebM; требуется исправный декодер FFmpeg.
- Для `запись.m4a` результат по умолчанию — `запись.txt` рядом с аудио.
- Для папки `Записи` результат по умолчанию — соседняя папка `Записи_text`.
- `--output` всегда задаёт **папку**, даже для одного файла.
- Вложенная структура сохраняется. Символические ссылки внутри папок пропускаются.
- Если в одной папке есть `запись.wav` и `запись.mp3`, имена текстов получают исходное расширение и короткий идентификатор, чтобы не совпасть.
- Текст записывается в UTF-8, с пунктуацией модели и простым разделением на абзацы по паузам между фрагментами. Отдельного редактора/LLM нет. Числа могут нормализоваться моделью: «десять часов» → `10:00`.
- Для тишины создаётся пустой `.txt`. Повреждённое аудио вызывает ошибку; очередь продолжает обработку других файлов.
- Готовый `.txt` появляется после успешной обработки всего файла. До этого промежуточный текст хранится в служебной базе.

## Длинные записи, остановка и повторный запуск

Длительность искусственно не ограничивается. FFmpeg читает запись последовательно. В буфере находится не более 23,2 секунды аудио; память модели от длины записи не зависит. Silero VAD работает на CPU и поставляется вместе с Python-пакетом. Он помогает выбирать паузы и пропускать тишину. Для очень тихой речи можно проверить результат с `--no-vad`.

На вынужденных стыках используются перекрытие и временные метки слов. Сопоставляются и текст, и интервалы, поэтому одинаковые слова в разных местах записи не удаляются. Метки приблизительны: полностью исключить ошибки на сложных стыках нельзя.

Нажмите `Ctrl+C`, затем повторите команду. Утилита продолжит с последнего сохранённого фрагмента. Декодеру может потребоваться прочитать начало сжатого файла, но завершённые фрагменты повторно не распознаются.

В папке результатов создаётся `.speech2text/`:

- `progress.sqlite3` — фрагменты, параметры и состояние очереди;
- `run.log` — диагностика ошибок;
- `whisper.log` — журнал native-движка, если использовался Whisper.

Состояние учитывает SHA-256 исходника, модель и её файлы, язык, параметры и версии движка. Несовместимые результаты не смешиваются. Сохраняется также информация о словах на стыке. Удаление `.speech2text` удаляет историю и возможность продолжить, но не готовые тексты.

Готовые неизменённые результаты пропускаются. Чужой или вручную отредактированный `.txt` не заменяется без `--overwrite`. Этот флаг заново обрабатывает завершённую запись и заменяет текст только после успеха. Если запуск с `--overwrite` был прерван, повтор той же команды продолжает незавершённую обработку.

Для сравнения моделей задавайте разные `--output`, сохраняя оба результата.

## Диагностика и коды завершения

```bash
uv run speech2text --help
uv run speech2text doctor
```

`doctor` проверяет FFmpeg и контрольные суммы моделей. Неподготовленная необязательная модель отображается в отчёте, но сама по себе не считается ошибкой команды.

Коды распознавания: `0` — всё обработано либо уже готово; `1` — частичный успех; `2` — ошибка параметров/подготовки или не обработан ни один файл; `130` — остановка через `Ctrl+C`.

## Проверка разработки

```bash
uv run pytest -q
uv run ruff check src tests scripts
```

Тесты не скачивают модели. Проверяются границы фрагментов, возобновление, сопоставление перекрытий, сохранность пользовательских файлов, пакетная обработка и контрольные суммы. Для тестов декодирования нужен FFmpeg.

Для сравнения качества подготовьте вручную проверенный эталонный `.txt`:

```bash
uv run python scripts/benchmark.py "запись.wav" "эталон.txt" --language ru --output "test-results/my-benchmark"
```

Скрипт последовательно запускает обе модели для русского или только Whisper для английского, сохраняет тексты и `report.json`. Время включает запуск процесса и проверку модели. WER считает замены, пропуски и добавления слов; регистр, пунктуация и «ё/е» игнорируются, но цифры и числительные к общей форме **не приводятся**. Поэтому «10:00» и «десять часов» увеличивают WER без обязательной смысловой ошибки.

Результаты локальной проверки и ограничения описаны в [результатах проверок](validation.md).
